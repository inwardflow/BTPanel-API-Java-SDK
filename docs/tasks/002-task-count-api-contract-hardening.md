# Task 002: GetTaskCountApi 契约化重构

## 状态

已完成

## 背景

`GetTaskCountApi` 仍保留旧式解析逻辑，主要问题包括：

- 仅凭“看起来像数字”来判断成功，契约表达不够清晰
- 遇到 JSON 响应时只简单标记为失败，没有真正解析业务载荷
- 对未知纯文本直接回退到 `0`，容易掩盖接口异常
- 缺少单元测试，JaCoCo 覆盖率为 0%

## 目标

- 明确接口的成功与失败响应契约
- 支持宝塔文档中的纯数字成功响应，同时兼容 JSON 包装响应
- 对无效响应 fail-fast，不再静默回退默认值
- 补充单元测试，覆盖成功、失败和异常路径

## 实施内容

- 重写 `GetTaskCountApi.parseResponse`
- 支持以下成功格式：
  - 纯数字文本，如 `0`
  - 带引号的数字文本，如 `"3"`
  - JSON 载荷，如 `{"status":true,"data":"5"}` 或 `{"count":7}`
- 保留失败 JSON 的 `status/msg`，交由上层客户端统一转换为异常
- 对缺失载荷、非法数字和无效纯文本直接抛出 `BtApiException`
- 新增 `GetTaskCountApiTest`

## 验收标准

- 文档示例 `0` 可被正确解析为成功结果
- JSON 成功与失败响应都能得到稳定、可预期的解析结果
- 非法响应不再默认回退为 `0`
- 主构建与单元测试通过
